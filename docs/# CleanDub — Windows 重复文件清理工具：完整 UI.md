# CleanDub — Windows 重复文件清理工具：完整 UI 与应用开发提示词

## 一、你的角色与开发目标

你是一名资深 Windows 桌面应用开发工程师、UI/UX 设计师和软件架构师。

请根据我提供的 CleanDub 三张 UI 概念参考图，实现一个真正可运行、界面精致、交互完整、具备实际文件处理能力的 Windows 桌面应用。

产品名称：CleanDub

产品定位：Windows 重复文件清理工具。

核心功能：扫描用户指定的文件夹，通过文件内容哈希识别重复文件，提供文件预览、重复文件分组、保留文件、清理文件、隔离文件、恢复文件、扫描历史和隔离区管理。

这不是一个静态网页，也不是只能演示的 UI 原型。最终交付必须是具有完整页面、真实交互、可执行文件操作和持久化数据的桌面应用。

**最高优先级：严格还原参考图的视觉风格，同时保证业务逻辑真实、文件操作安全、项目可以正常运行和构建。**

如果参考图中存在不合理的实现细节，可以优化内部架构，但不要擅自改变整体视觉设计方向。

## 二、技术栈与工程要求

请优先使用以下技术栈：

- 桌面容器：Tauri 2
- 前端框架：React 19 + TypeScript
- 构建工具：Vite
- 样式方案：Tailwind CSS 或 CSS Modules，选择一种并保持统一
- 图标：Lucide React
- 后端：Rust
- 数据存储：SQLite
- 文件哈希：SHA-256
- 文件系统操作：Rust 标准库及经过验证的文件系统 API

如果当前开发环境不支持 Tauri，请先检查实际环境，并选择可运行的替代方案，例如 Electron + React + TypeScript。不要同时混用多个桌面容器。

要求：

1. 使用清晰、模块化的项目结构。
2. 前后端职责分离，文件系统操作必须由可信的后端执行。
3. 所有重要交互都必须真正生效，不允许使用没有功能的装饰性按钮。
4. 不要将所有代码堆积在一个 App.tsx 文件中。
5. 不要只输出代码片段、伪代码或设计说明，必须实际创建完整项目文件。
6. 所有核心页面都应实现，不要只开发首页。
7. 使用严格的 TypeScript 类型定义，避免滥用 any。
8. 为长时间运行的扫描任务提供进度反馈、取消能力和错误处理。
9. 提供完整的安装依赖、启动开发环境、构建 Windows 应用的命令。
10. 如果开发环境允许，实际执行构建和测试，修复发现的问题。

### 6.2 左侧文件类型筛选栏

### 6.3 重复文件分组列表

每个重复文件组采用清晰的卡片或列表布局。

展示：

- 文件类型图标或缩略图。
- 文件名。
- 重复文件数量。
- 文件大小。
- 文件格式。
- SHA-256 哈希摘要。

文档文件：

- 使用简洁的文档图标。
- 展示扩展名、大小和路径。

其他文件：

- 使用对应文件类型图标。
- 不得因文件无法预览而无法参与重复文件识别。

长文件路径需要截断显示，并通过 Tooltip 或详情面板展示完整路径。

### 6.4 重复文件识别逻辑

必须采用真实的内容校验机制。

建议采用以下流程：

第一阶段：枚举指定目录中的文件。

第二阶段：按照文件大小对文件分组。

第三阶段：对于大小相同的候选文件，计算 SHA-256。

第四阶段：只有大小相同且 SHA-256 相同的文件才进入同一个重复文件组。

第五阶段：展示实际重复文件分组。

注意：

- 文件名相同不代表文件内容相同。
- 文件名不同但内容相同的文件也必须识别出来。
- 文件大小相同不代表文件内容相同。
- 哈希计算应采用流式读取，避免一次性将大文件全部载入内存。
- 文件在扫描过程中可能被修改或删除，需要处理读取失败和文件状态变化。
- 对无法读取的文件进行记录和提示，不要直接忽略错误。
- 同一个文件不得因为多条扫描路径被重复计数。
- SHA-256 相同的文件可视为内容重复候选；执行高风险操作前仍需检查文件当前状态。

### 6.5 保留文件

每个重复文件组必须允许用户指定一个保留文件。

提供按钮：

保留此文件

行为：

1. 将该文件标记为此组的保留文件。
2. 默认不对该文件执行清理或隔离。
3. 显示清晰的“保留”标记。
4. 允许用户更改保留文件。
5. 在未明确指定保留文件时，不得对该组自动执行破坏性操作。

建议为每组重复文件默认选中一个候选保留文件，但必须明确显示这个选择只是建议，用户可以修改。

### 6.6 清理文件

危险操作按钮：

清理

按钮颜色：

#CF222E

行为：

1. 清理操作默认仅针对用户明确选中的重复文件。
2. 不得清理已标记为保留的文件。
3. 执行前显示确认对话框。
4. 对话框显示将处理的文件数量、文件路径和预计释放空间。
5. 明确说明清理可能导致数据无法恢复。
6. 再次检查文件是否存在及其状态是否与预期一致。
7. 执行完成后展示成功、失败和跳过的文件数量。
8. 记录操作历史。

默认建议优先提供隔离操作，不要默认永久删除文件。

如果实现永久删除功能，应将其与隔离区操作明确区分，并提供更严格的确认步骤。

### 6.7 隔离文件

按钮：

隔离

颜色：

使用中性或蓝色按钮，不使用危险红色。

行为：

1. 将用户选中的重复文件移动到应用专用隔离区。
2. 默认不隔离已标记为保留的文件。
3. 隔离前进行确认。
4. 在隔离区中保存原始文件路径、文件名、大小、SHA-256、隔离时间和必要的恢复信息。
5. 在跨磁盘移动时采用安全的复制、校验、提交、删除源文件流程。
6. 校验失败时保留源文件，并清理不完整的临时副本。
7. 更新重复文件分组和可释放空间统计。
8. 记录操作结果。

隔离区应采用专用目录，并避免被普通扫描任务重新扫描。

### 6.8 文件预览与详情

点击文件行或预览按钮后打开详情面板。

展示：

- 文件名。
- 完整路径。
- 文件大小。
- 创建时间和修改时间（系统能够获取时）。
- SHA-256。
- 所属重复文件组。
- 当前保留或隔离状态。
- 预览内容或系统默认打开操作。

不支持预览的文件应显示明确的类型信息，而不是显示错误图片。

恢复流程：

1. 检查原始路径是否仍然有效。
2. 检查原位置是否已存在同名文件。
3. 如果目标路径发生冲突，提示用户选择其他路径或取消恢复。
4. 恢复后验证文件完整性。
5. 只有确认恢复成功后，才更新隔离区记录。
6. 恢复失败时保留隔离文件。
7. 记录恢复操作结果。

永久删除流程：

1. 明确提示无法通过应用恢复。
2. 显示选中文件数量和文件名。
3. 要求用户再次确认。
4. 删除前验证隔离文件路径属于应用管理的隔离区。
5. 不允许将任意外部路径当作隔离文件直接删除。
6. 记录成功或失败状态。

### 7.6 设置入口

可以实现以下基础设置：

- 默认扫描目录。
- 是否包含隐藏文件。
- 是否跟随符号链接。
- 默认文件预览行为。
- 隔离区位置。
- 是否在清理前要求二次确认。

对于可能引起循环扫描、越权访问或大量重复遍历的选项，应提供合理限制和说明。

## 九、文件操作安全规范

这是一个会修改用户文件的工具，安全性必须优先于操作速度。

1. 默认不自动删除文件。
2. 不得未经用户确认执行批量永久删除。
3. 保留文件必须始终受到保护。
4. 不允许将隔离区目录作为普通扫描根目录。
5. 执行文件操作前重新验证文件是否存在。
6. 防止路径遍历和任意路径删除。
7. 对符号链接、权限不足、只读文件和文件占用情况进行妥善处理。
8. 不要直接信任前端提交的路径。
9. 后端必须自行验证文件路径、隔离区路径和允许执行的操作。
10. 跨磁盘移动必须进行内容校验。
11. 操作中断或应用崩溃时，不应导致源文件和目标文件同时丢失。
12. 不允许在校验失败时删除原始文件。
13. 批量操作应生成清晰的结果报告。
14. 使用最小必要权限，不要求管理员权限运行。
15. 所有文件操作应有明确的用户可见反馈。
16. 如果文件在扫描之后发生变化，应重新检查其大小、哈希或文件状态。
17. 对硬链接、符号链接、文件系统边界和重解析点制定明确处理策略。
18. 不要宣称任何清理方式绝对安全，应提供可理解的风险提示。

对于无法安全处理的文件，应跳过操作并说明原因，而不是强行执行。
